# Проверки нативного этапа 0.2 — 17.09.2026

## Итог

- CMS: **8/8** Node.js-тестов.
- Go на Windows: **16/16**, с реальным локальным MQTT-брокером и отдельным собранным процессом.
- Go на Linux: **17/17** в Docker Linux-контейнере, включая тот же брокер, отдельный Linux-процесс и Unixgram-уведомление systemd.
- `go vet ./...` — без замечаний.
- Windows exe и Linux amd64 собраны; Linux без CGO.
- Синтаксис `server.mjs`, `public/app.js`, `agent/start-demo.mjs`, `agent/web/renderer.js` проверен.
- HTTP главной Go-панели — 200; три реальных агента в CMS — Online; три `/health` отвечают версией 0.2.0.

Компилятор — переносимый официальный Go 1.27.1, архив проверен по SHA-256 из официального списка загрузок. ОС компьютера — Windows. Лабораторный MQTT — eclipse-mosquitto:2, loopback 18884; после прогона временный брокер и его сеть удалены. Остальные Docker-проекты не изменялись.

## Что именно проверено Go-тестами

1. Эксклюзивная блокировка данных: второй агент не открывает ту же SQLite; закрытие освобождает блокировку.
2. Manifest: device ID, размеры, квота, whitelist MIME.
3. Короткая загрузка → сохранение `.part` → Range 206 → проверенный полный файл.
4. Сервер отвечает 200 вместо Range: файл заменяется, не склеивается с повторной копией.
5. Неверный SHA-256: ни готового файла, ни непригодного `.part`.
6. Квота удаляет устаревший hash-файл, сохраняет прикреплённый и неизвестный пользовательский файл; overflow отклонён.
7. Команды: повторный ID не делает второй next, дедупликация и пауза переживают переоткрытие SQLite; stale session отклоняется.
8. ACK удаляет только отправленные подтверждённые ID; чужой ACK не теряет другие события.
9. Checkpoint изображения сохраняет playedMs; временное окно переключает локальный fallback.
10. Мост: без токена 401, чужие Host/Origin 403, cross-site bootstrap не выдаёт cookie, защищённый `/metrics` доступен с токеном.
11. Реальный WebSocket: состояние получено; второй renderer не допущен; disconnect завершает старую сессию и создаёт новую.
12. OTA: валидная Ed25519-подпись и загрузка `.candidate`; повторный sequence, повреждённая подпись и чужая платформа отклонены; файл не исполняется.
13. MQTT options: удалённый plain TCP запрещён, TLS не отключает проверку сертификата, wildcard topic отклонён.
14. Неудачный ACK оставляет PoP в SQLite; успешный ACK освобождает очередь; offline не удаляет подготовленный manifest и кеш.
15. Настоящий брокер: QoS 1 next → ACK; повторная доставка не делает второй next; pause работает.
16. **Отдельный exe / Linux binary**: скачивает медиа, отдаёт мост, получает ACK, переживает offline CMS; принудительно уничтожен; после нового запуска восстанавливает кеш/расписание/паузу и события, затем доставляет очередь при reconnect.
17. Только Linux: READY/WATCHDOG отправлены и прочитаны через настоящий локальный Unixgram socket.

Проверки 15 и 16 опциональные, включаются переменными окружения из README. В указанном финальном прогоне обе были включены, не skipped. Linux выполнялся в сетевом пространстве только лабораторного MQTT-контейнера. Тестовые базы, ключи и конфигурации — временные, не `agent/data` рабочего стенда. Process-тест использует синтетические renderer-отчёты и тестовые байты, **не декодирует настоящее видео**.

## Чего этот прогон не доказывает

- Новый браузерный renderer не проходил отдельный браузерный UI/видео-прогон в этом этапе; проверены его синтаксис, HTTP и протокол моста. Скриншоты и 11 браузерных сценариев прежнего этапа относятся к 0.1.
- Реальный kiosk Chromium и supervisor/watchdog под Astra; установка systemd-службы; графическая сессия и sandbox.
- VA-API, GPU, конкретные драйверы/кодеки, 4K, монитор/аудитория и бесшовные переходы.
- Физическое отключение питания, отказ накопителя, 48 часов offline, ±500 мс и устойчивость под нагрузкой.
- Production TLS/MQTT broker/ACL, индивидуальные credentials, пользовательская авторизация CMS и полный аудит безопасности.
- Полный OTA: установка, reboot, health-gate и A/B rollback. Реализован и проверен только staging подписанного кандидата.
- API/CMS заказчика и совместимость с Xibo: агент работает с собственным manifest API.
- Аппаратный watchdog и systemd RuntimeWatchdog: настройки хоста не менялись.

Это первый нативный вертикальный срез, не утверждение о промышленной готовности. Для следующей приёмки нужны точная Astra/build и целевой мини-ПК.
