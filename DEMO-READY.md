# Презентационный стенд — холодный старт и проверка

## Запуск за 2–3 минуты (заложить 5 минут)

1. Запустить Docker Desktop и дождаться готовности Engine.
2. В папке проекта дважды нажать `cold-start-demo.cmd` либо выполнить:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/restart-demo.ps1
```

Скрипт останавливает свои Go-агенты и Player Control на 8787, выполняет
`docker compose -f reference-xibo/compose.yaml down`, затем `up -d --wait`,
проверяет страницу входа CMS, запускает Player Control и 100 Go-процессов.
Все именованные volumes сохраняются. Нельзя добавлять `down -v`.
Проекты camerayolo7 и ai_video_intelligence_demo не затрагиваются.
Окна серверов скрыты; их закрытие вместе с окном запуска не требуется.

Успех: `Ready: 100/100 real Go agents online`.
Если сообщение не появилось, смотреть `tmp/server.err.log`,
`tmp/agents.err.log`, `tmp/agents/go-agent-NNN.log`.
Для перезапуска только Player Control и агентов: `start-100-go-agents.cmd`.
Не запускать дополнительно старый `start-go-demo.cmd` — это отдельный парк из трёх агентов.

3. Открыть:
   - Player Control: http://127.0.0.1:8787/?agents=go
   - Реестр: http://127.0.0.1:8787/fleet.html
   - CMS: http://127.0.0.1:8088/
4. В уже открытом браузере нажать **Ctrl+F5**: картинки старого логотипа
   могут оставаться в кеше. Свежий адрес http://localhost:8088/ также
   подходит для проверки. Учётные данные CMS остаются прежними.

## Что исправлено

Верхняя карточка раньше считала `/api/state` и свежие сообщения iframe
каждые 2 секунды. Сетка независимо запрашивала
`/api/fleet?demo=100&includeReal=1` каждые 10 секунд. Сервер дополнял
реальные устройства синтетическими записями, назначая им статусы по остатку
от деления номера на 7 и 17. Поэтому «3 живых» и преимущественно зелёная
сетка описывали разные сущности. Это не рассинхронизация WebSocket и XMR.

На машине действительно работал `agent/start-demo.mjs` и только три
`go-screen-0N`. В Docker нет контейнера-координатора `dooh-xibo-reference`:
это имя Compose-проекта CMS. `reference-xibo/player-server.mjs` — отдельный
сторонний PWA proxy на 8789. Наши Go-агенты получают manifest и отправляют
heartbeat непосредственно в `server.mjs` на 8787; XMDS/XMR не участвуют.

Теперь верхняя карточка и сетка обновляются одной функцией из одного
ответа `/api/fleet?scope=go100&pageSize=100` каждые 2 секунды. В этом парке
только реальные `go-agent-001…100`. Online означает heartbeat младше
10 секунд, отсутствие принудительного offline и ошибки агента.
Просроченная ошибка не маскирует потерю связи: статус становится offline.
При недоступности API оба счётчика показывают «—». Старые записи и внешние
дисплеи сохранены, но не подмешиваются в этот парк. Симуляция доступна
только при явном `fleet.html?mode=demo` и подписана как демонстрационная.

Запускаются 100 отдельных Go-процессов с разными портами 8891–8990,
каталогами SQLite и логами. Старт разнесён на 35 мс. Вывод агентов больше
не теряется в `stdio: ignore`; ошибка запуска/выход видна в логе.
Предпросмотр панели открывает три iframe. Online 100 агентов не означает
100 физических экранов или 100 активных браузерных рендеров; журнал
показов содержит только фактически присланные события.

## Брендинг CMS

По коду установленной CMS проверены `ConfigService::loadTheme()`,
`getBrandConfig()`, `getBrandAssetFile()`, контроллеры Login/User и Twig.
В этой сборке бренд читается из `library/brand/config.json`; старый
каталог `web/theme/custom` больше не используется. В проверенных
настройках Configuration/General нет формы переименования бренда.

`reference-xibo/brand/` содержит `appName/productName = Player Server`,
светлый/тёмный SVG-wordmark, SVG-иконку, favicon, PNG-иконки и небольшую
CSS-правку ширины логотипа. Файлы подключены read-only bind mounts в
Compose и сохраняются при пересоздании контейнера. PHP, API, таблицы,
контейнеры и сервисы не переименовывались.

Administration → Settings → General → «Включить последние новости?»
выключено штатной настройкой, сохранённой CMS в базе. CSS убирает пустую
карточку выключенной ленты. Исходные юридические сведения в «О программе»
и ссылка на исходный код сохранены; там название Xibo остаётся. Это
известное ограничение, полное удаление всех упоминаний не заявляется.

## Проверка за 10 минут перед показом

1. **0–2 мин:** холодный старт, дождаться Ready; не открывать старый
   запускатель трёх агентов.
2. **2–4 мин:** открыть Player Control. Верхний счётчик = счётчику сетки;
   ожидается 100/100, минимум 90. Ошибок 0. Обновить страницу, проверить
   три живых предпросмотра, появление новых реальных событий.
3. **4–5 мин:** реестр — источник Go-плееры, 100 записей, 0
   демонстрационных; lastSeen обновляется каждые несколько секунд.
4. **5–7 мин:** CMS — Ctrl+F5, проверить Player Server в сайдбаре и
   заголовке; открыть Кампании, Расписание, Медиатеку. Отдельно открыть
   `/login`, проверить логотип, не выходя из рабочей сессии.
5. **7–9 мин:** проверить логи и короткий прогон:

```powershell
node tools/soak-demo.mjs 60
docker compose -f reference-xibo/compose.yaml ps
```

6. **9–10 мин:** вернуться в Player Control. Сверить счётчики ещё раз;
   оставить ноутбук включённым, Docker Desktop работающим. Не проводить
   тестовые отключения непосредственно перед показом.

Для повторения полной приёмки: `node tools/soak-demo.mjs 1800`.
Он только читает API, сохраняет все 100 статусов/lastSeen каждые 2 секунды
в `tmp/soak/*.jsonl`, проверяет минимум 90 online, отсутствие ошибок,
согласованность summary/items и движение heartbeat каждого агента.
`tmp/soak/latest.json`: `complete=true` и `passed=true` означают окончание
успешного прогона; до завершения `passed=false` нормально.

## Откат

До правок создан Git baseline `3753602` на ветке `demo-preparation`.
Согласованная копия Player Control SQLite: `tmp/demo-backup/dooh.sqlite`;
исходные файлы CMS brand: `tmp/demo-backup/cms-brand/`.
Секреты `.env.local`, рабочие базы и логи не коммитятся.

Для отката исходников сначала сохранить новые пользовательские правки,
затем отменить коммит исправлений через `git revert <commit>` и
перезапустить соответствующий стенд. Для отдельного отката брендинга
убрать mounts `./brand/*` из Compose и пересоздать `cms-web`: исходные
файлы остаются под mounts в именованном volume. Новостную ленту можно
снова включить той же настройкой General. Рабочую базу не восстанавливать
из старой копии без необходимости: это потеряет более новые события.

Детальные результаты текущей проверки записаны в `reports/demo-verification.md`.
