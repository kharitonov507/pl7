# Результаты проверки прототипа

**Этап 0.2, 17.09.2026:** отдельный нативный Go-агент добавлен и проверен. Результаты — [agent/VERIFICATION.md](agent/VERIFICATION.md). Ниже сохранён отчёт браузерного этапа 0.1; его 11 браузерных сценариев не являются проверкой нового Go-рендера. Серверный набор теперь расширен до 8 тестов.

Проверено на Windows, Node.js 24.15.0 и Microsoft Edge через автоматизированный браузерный прогон.

## Сервер: 6 тестов

1. Три устройства и исходные плейлисты доступны.
2. Имитация offline блокирует API выбранного плеера, но оставляет панель управления доступной; reconnect восстанавливает API.
3. Повторная доставка PoP не создаёт дубликаты; некорректный пакет не записывается частично.
4. Валидация плейлистов и временных окон; версия manifest увеличивается.
5. Команды, фильтрация форматов загрузки, byte-range и отклонение чужого Origin.
6. Настройки и события остаются после закрытия и повторного открытия серверной SQLite.

## Браузер: 11 сценариев

1. Запуск трёх независимых плееров, кеш и heartbeat.
2. Offline одного плеера: контент продолжает воспроизводиться, PoP остаётся в локальной очереди.
3. Reconnect: доставка накопленных событий, отсутствие дубликатов UUID.
4. Пауза фиксирует elapsed; resume продолжает показ.
5. Назначение плейлиста через диалог панели; новый manifest применяется плеером.
6. Загрузка настоящего WebM, Blob-кеш, воспроизведение и completed по окончанию.
7. Временное расписание: fallback → основной плейлист → fallback.
8. Отображение и фильтрация журнала.
9. Реальный остановленный сервер: кешированное воспроизведение продолжается, reload плеера восстанавливается через Service Worker и IndexedDB.
10. Ширина 390 px: нет горизонтального переполнения.
11. Нет необработанных JavaScript-ошибок страниц.

## Что не проверено

Astra Linux, Go, x86-мини-ПК, VA-API, 4K, аппаратные сбои питания, физический дисплей, длительный soak test, MQTT, OTA, API заказчика и production-нагрузка.

Прогоны используют отдельные временные БД; серверная data/ рабочего стенда не очищается. В test-results/ сохраняются скриншоты dashboard, offline, журнала и мобильного представления.
