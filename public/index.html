Демо за 3 минуты
  1. Покажите три экрана с разными плейлистами.
  2. Нажмите «Отключить связь» у экрана 03. Показы продолжаются, очередь растёт.
  3. Верните связь: события догружаются в журнал.
  4. Откройте «Настроить» и смените плейлист или задайте временной интервал.
  5. Покажите журнал и скачайте отчёт.

Отключается обмен выбранного плеера с API. Это имитация сбоя связи, не физическое отключение сети.

ПЛЕЙЛИСТЫ И РАСПИСАНИЯ

Плейлисты.

Создайте цикл материалов, затем назначьте его экрану и задайте период показа через «Настроить».

Где настраивать: плейлист создаётся здесь; расписание, основной и резервный плейлисты назначаются конкретному экрану в «Живые плееры» или «Все экраны» → «Настроить». Пустые даты означают постоянный показ.

ГРАНИЦЫ ПРОТОТИПА

Как устроен стенд.

Player Control — единая панель; Player CMS — серверный слой хранения и интеграции.

01 / ЦЕНТР УПРАВЛЕНИЯ

Player Control + HTTP API

Здесь оператор загружает контент, создаёт плейлисты, назначает расписания, управляет экраном и смотрит отчёты.

↓
02 / СЕРВЕРНЫЙ СЛОЙ

Player CMS · SQLite · OAuth

Сервер хранит метаданные, синхронизируется с подключённым CMS-движком и не показывает его бренд в рабочем интерфейсе.

↓ HTTP + MQTT
03 / НЕЗАВИСИМЫЕ ПЛЕЕРЫ

Browser + Go agent

У каждого свой идентификатор, расписание, проверяемый кеш и очередь proof-of-play для отправки после восстановления связи.

Настройка экрана

Без дат основной плейлист работает постоянно. Вне интервала включается резервный. Изменения поступят online-плееру после кеширования.
